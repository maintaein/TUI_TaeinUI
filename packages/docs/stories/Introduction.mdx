# TUI - TaeinUI

> 컴포넌트마다 다른 움직임을 갖는 React UI 컴포넌트 라이브러리

## 무엇을 파는가

MUI·Radix·shadcn은 전 컴포넌트에 같은 전환 하나를 적용합니다. 예측 가능성이 그들의
가치이기 때문입니다. TUI는 반대쪽을 택합니다 — 컴포넌트 각각이 자기 성격에 맞는 모션을
갖고, 그래서 어떤 컴포넌트를 집어도 그 컴포넌트만의 움직임이 남습니다.

통일성을 내려놓는 범위는 **모션까지**입니다. 색·간격·타이포·접근성의 통일성은 그대로
지키고, **시인성·가독성·가시성은 협상 대상이 아닙니다** — 모션이 이 셋 중 하나라도 깎으면
틀린 쪽은 모션입니다.

### 사실 확인

- **컴포넌트 패밀리 30개** (top-level export 49개 — 차이는 `ModalHeader`·`CardBody`처럼 개별 import도 되는 하위 컴포넌트)
- **GSAP이 모션의 메인 런타임** — 현재 12개 컴포넌트가 GSAP으로 움직입니다
- **Zero-runtime CSS** — Vanilla Extract, 빌드 타임에 CSS 생성. Tree-shaking 지원
- **TypeScript 엄격 모드**, `any` 미사용
- **WCAG 2.2 AA** — 본문 대비 4.5:1과 포커스 링 폭을 테스트로 잠가 두었습니다
- **런타임 의존성 4개** — `@vanilla-extract/css`, `@vanilla-extract/recipes`, `clsx`, `gsap`

## 🚀 빠른 시작

### 1. 기본 사용법

```tsx
import { Button, TextField, Card } from '@taein-ui/core';
import '@taein-ui/core/styles.css';

function App() {
  return (
    <Card>
      <TextField
        label="이메일"
        type="email"
        placeholder="example@email.com"
      />
      <Button variant="primary">
        로그인
      </Button>
    </Card>
  );
}
```

### 2. 폼 컴포넌트

```tsx
import { TextField, TextArea, Checkbox, Switch, Button } from '@taein-ui/core';
import { useState } from 'react';

function ContactForm() {
  const [formData, setFormData] = useState({
    name: '',
    email: '',
    message: '',
    subscribe: false,
  });

  return (
    <form>
      <TextField
        label="이름"
        value={formData.name}
        onChange={(e) => setFormData({ ...formData, name: e.target.value })}
        required
      />

      <TextField
        label="이메일"
        type="email"
        value={formData.email}
        onChange={(e) => setFormData({ ...formData, email: e.target.value })}
        required
      />

      <TextArea
        label="메시지"
        value={formData.message}
        onChange={(e) => setFormData({ ...formData, message: e.target.value })}
        height={150}
      />

      <Checkbox
        label="뉴스레터 구독"
        checked={formData.subscribe}
        onChange={(e) => setFormData({ ...formData, subscribe: e.target.checked })}
      />

      <Button type="submit" variant="primary" fullWidth>
        보내기
      </Button>
    </form>
  );
}
```

## 🎬 모션

GSAP 런타임이 실제로 붙어 있는 컴포넌트입니다. 계획이 아니라 코드에서 읽은 목록이고,
여기 없는 컴포넌트는 CSS 트랜지션만 씁니다.

| 컴포넌트 | GSAP이 맡는 일 |
|---|---|
| Modal | 타임라인 상대 위치 · 트리거 좌표 읽기 |
| BottomSheet | 타임라인 상대 위치 · 터치 드래그 1:1 추적 |
| SideSheet | 타임라인 상대 위치 |
| Snackbar | 카운트다운 진행률 read-back |
| Checkbox | 모양 변형(checked ↔ indeterminate) · 다중 목표 중단 |
| Switch | 타임라인 상대 위치 · 다중 목표 중단 |
| SegmentedButtons | 인디케이터 좌표 읽기 · 다중 목표 중단 |
| NumericSpinner | 다중 목표 중단 |
| Slider | 드래그 중 값 따라붙기 |
| HeaderBarNav | 포인터 근접 추적 · 컨테이너 좌표 읽기 |
| TextField, TextArea | 줄바꿈 감지용 offsetTop 읽기 |

GSAP은 "쓸 수 있으니 쓴다"가 아니라 CSS로는 못 하는 일이 있는 자리에만 들어갑니다.

`prefers-reduced-motion: reduce`에서는 CSS 전역 규칙이 트랜지션·애니메이션을 끄고,
전역 규칙이 닿지 않는 GSAP 트윈은 각 훅이 끝 상태로 확정한 뒤 멈춥니다. 중간 프레임에
멈추는 경우가 구조적으로 없습니다.

왼쪽 사이드바에서 컴포넌트를 골라 컨트롤을 바꿔 보면 각자의 움직임을 확인할 수 있습니다.

## ♿ 접근성

- WCAG 2.2 AA 기준. 모션을 강하게 쓰는 라이브러리일수록 여기서 무너지기 쉽기 때문에
  장식이 아니라 전제로 둡니다
- 본문 대비 4.5:1, 비텍스트 대비 3:1 — 흰 배경이 아니라 더 불리한 `background.paper`
  기준으로 판정합니다
- 시맨틱 HTML, ARIA 속성, 키보드 네비게이션, 오버레이 포커스 트랩
- 포인터 타깃 24×24 CSS px(2.5.8) 하한, 기본은 44×44
